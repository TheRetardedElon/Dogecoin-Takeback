Source of truth

How we decide what is real when memory, chat logs, old markdown, and code disagree.

Priority order

  1. Code that compiles and runs — behavior of the binaries is final.
  2. This HTML docs site (html/docs/) — living recovery knowledge; update when we learn something.
  3. Automated scans — rebrand residual counts, greps, test results.
  4. Root project markdown — DOGECOIN_CHANGELOG.md, plans, architecture notes — historical, may overclaim.
  5. Chat transcripts (Gemini, etc.) — design intent only until reflected in code/docs.
  6. Memory of lost HDD work — rebuild tickets, not assumptions of presence.

Backup doctrine

Single-disk is how we got here After Git is restored: at least one remote (GitHub/GitLab) and one offline copy. Docs and diagrams live in the same repo as code.

How to update these docs

  • Edit HTML under html/docs/ (same look via assets/styles.css).
  • Keep the sidebar nav links in sync when adding a page.
  • Record dates on dashboard / build log when status changes.
  • Prefer short factual updates over rewriting history.
