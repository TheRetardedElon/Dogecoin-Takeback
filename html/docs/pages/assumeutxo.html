AssumeUTXO (1.14 DNA)

Make a full node wallet-usable in minutes by loading a attested UTXO snapshot at height H, while fully validating genesis→H in the background. Not a soft fork — temporary bootstrap trust until hash proof completes.

Design: doc/assumeutxo-dogecoin-1.14.md Engineering: A–D3 done Product: P1 ~90% (CDN + dialog packaged) Attested: mapAssumeutxo[6324519]
Mainnet attestation (2026-08-09) Height 6324519 is in mapAssumeutxo with hash_serialized=a2fde0b7…c6762a. CDN artifact (~11 GB): https://sync.doge.gopastearth.com/utxo-6324517-20260809T065442Z.dat · file SHA-256 0c407452…0ad026. Other heights still need -assumeutxodev=1 or a new map entry. Product plan: doc/tiered-storage-and-fast-sync.md.
Two hashes (do not confuse) hash_serialized = hash of the UTXO set at height H (already in AssumeutxoData). CDN artifact digest = hash of the snapshot file bytes (Product P1 stream-and-hash). Both must pass; fail closed.

Snapshot file format (B1)

Dogecoin 1.14 still uses per-txid CCoins (not modern Bitcoin per-outpoint Coin). Version 1 marks that layout: 

magic "utxo\xff" | uint16 version=1 | network magic[4]
base_blockhash | coins_count
repeat: txid | CCoins serialization

Background validation (C1/C2)

  • Expected UTXO hash frozen at loadtxoutset via ComputeCoinsHashSerialized (same idea as gettxoutsetinfo.hash_serialized).
  • Each ActivateBestChain steps up to 32 background blocks; RPC stepbackgroundvalidation for manual push.
  • Match → assumeutxo_validated + dual collapsed.
  • Mismatch / ConnectBlock fail → fail-closed (error UI + shutdown). Remove assumeutxo.dat + chainstate_snapshot/ to recover.
  • C2: historical getdata even when blocks are ancestors of chainActive but lack BLOCK_HAVE_DATA (prune case).
