MemeStream + Dogecoin Core integration

Handoff for rebuilding the client-side Meme Stream tab in Dogecoin Core / Qt. Captured from GPE (GoPastEarth) side discussion — 2026-07-28.

Status: spec only — no memestream sources in this tree yet API host: https://gopastearth.com SPA: https://memestream.gopastearth.com
Secrets stay out of git Publish key and any RPC credentials live in local config / env only (-memestreamkey=, GPE .env). Never commit production keys. Wrong or missing publish key → 401 client_only — not a GPE user login.

Two separate systems (do not mix)

SystemDirectionPurpose
A. MemeStream Dogecoin Core/Qt → HTTPS → GPE API Feed, publish, upload, soft “Wow” likes
B. POS DOGE payments GPE backend → RPC → local dogecoind Invoices, watchers, walletnotify

MemeStream does not use Dogecoin Core RPC. Core only needs an HTTP client + publish key + a wallet address. POS crypto on the GPE server uses DOGE_RPC_* — unrelated to posting memes.

A. MemeStream (what Core must implement)

Product policy

SurfacePost?Author
Web SPA https://memestream.gopastearth.com No (view + Wow only) n/a
Dogecoin Core / Qt Yes DOGE address = author + tipAddress

Shared secret (required for posts)

ItemValue / rule
Env on GPEMEMESTREAM_PUBLISH_KEY
Core CLIdogecoin-qt -memestreamkey=<same key>
Preferred headerX-MemeStream-Key: <key> only
Also acceptedAuthorization: MemeStream <key> or body memestreamKey
NeverAuthorization: Bearer …, X-Api-Key, GPE login/JWT

Scope of this key (hard-enforced on GPE):

  • Allowed: POST publish, POST upload (≤69 KiB)
  • Denied: any other platform API (POS, admin, tenants, sessions, etc.)

MEMESTREAM_PUBLISH_OPEN=1 would allow keyless publish — must stay unset in prod.

Publish body (JSON)

POST https://gopastearth.com/api/memes
Content-Type: application/json
X-MemeStream-Key: <from local config>

{
  "title": "Follow your dreams",
  "body": "such wow",
  "wallet": "DYourReceivingAddressFromCoreWalletxxxx"
}

Wallet field aliases: wallet (preferred), author, address, fromAddress, from, or header X-Doge-Address.

Server forces:

  • source = dogecoin-client
  • tipAddress = author (same wallet)

Missing address → wallet_required (key can still be fine).

Tips (on-chain, in Core)

No GPE bridge for tips After feed load, each item has tipAddress / author (DOGE address). Core one-click tip = send DOGE to that address on-chain via the normal wallet.

Likes (“Wow”)

  • Public soft counter; once per identity.
  • Core should send X-Doge-Address: <wallet> (or body wallet).

Core UI sketch (from recovered Core Pro screenshots)

  1. Home right-rail — compact Meme Stream cards + Tip CTAs (always visible while browsing balance/activity)
  2. Dedicated Meme Stream nav page — full publish form + searchable feed + Like / Tip / Boost (better scrolling)
  3. Identity — author = Core wallet receive address (no separate username). Same address is tip target.
  4. Publish with X-MemeStream-Key + that wallet; Tip opens Send pre-filled to creator address
  5. Optional: “View on web” → SPA https://memestream.gopastearth.com (view-only)
  6. Serious Mode can hide both rail + nav entry (local preference)

curl -sS -X POST 'https://gopastearth.com/api/public/memestream/publish' \
  -H 'Content-Type: application/json' \

Master Admin (Meme Stream manager UI) uses master_admin session for delete/feature — not the Core publish key.

B. POS Dogecoin Core node (server-side — different path)

GPE backend talks to local dogecoind for POS crypto (not for MemeStream posting). Env on GPE: DOGE_RPC_URL, DOGE_RPC_USER, DOGE_RPC_PASS, watch intervals, master addresses, etc. Sample conf shape in GPE repo: app/configfiles/dogecoin.conf.

walletnotify hits GPE backend for invoice reconciliation — unrelated to MemeStream publish.

Checklist for rebuilding Core + MemeStream

  • Ship/build Qt with Meme Stream tab + -memestreamkey=
  • Set key from GPE MEMESTREAM_PUBLISH_KEY (local only)
  • Always send X-MemeStream-Key on publish/upload
  • Always send receiving wallet on publish
  • Feed: GET canonical feed URL
  • Images ≤69 KiB; tip on-chain to tipAddress
  • Do not use MemeStream key for RPC or POS

What Core does not need

  • GPE user login / JWT / master_admin
  • Tenant IDs / POS device secrets
  • Dogecoin RPC credentials (unless you also run POS crypto on that machine)
  • Bridge software for MemeStream tips
