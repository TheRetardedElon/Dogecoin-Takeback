Storage stack

Current engines, planned replacements, and how to migrate without breaking the network. Implementation of replacements is not present in this tree yet — this page captures the engineering plan.

Current state

DataEngineCode surface
Chainstate / block index (KV) LevelDB dbwrapper.*, txdb.*, embedded src/leveldb/
Raw blocks Filesystem flat files blocks/blk*.dat, rev files
Wallet Berkeley DB (default) wallet/db.*, walletdb.* (batch composition); format probe + walletdb_backend.*
Peers / bans Custom flat / serialize addrdb.*, peers.dat style

Full dual-stack plan: SQLite wallet plan (Phase A detection + Phase B batch abstraction landed).

Target options (from prior design work)

ComponentPragmaticEco / performance oriented
Chainstate RocksDB (LevelDB-like API) libmdbx (mmap B+ tree; MRSW, map size policy)
Wallet SQLite + read-only BDB + migratewallet

Why the network does not crash

Consensus is validation + P2P, not disk format Node A on LevelDB/BDB and Node B on RocksDB/SQLite can share the same network if they enforce the same rules and speak the same protocol. Deploy as optional client upgrades; require reindex or migrate tools for local data only.

Engineering friction (real, not marketing)

CDBWrapper / LevelDB

  • Obfuscation of chainstate values (AV false-positive mitigation)
  • -dbcache and memory accounting assumptions
  • Iterator / batch semantics used throughout validation
  • Full re-validation of dbwrapper_tests and IBD

libmdbx specifically

  • Multiple-reader / single-writer model may need write serialization redesign
  • Fixed maximum map size vs organic LevelDB growth
  • Idle CPU of the database drops; the node event loop does not

Wallet SQLite

  • Dogecoin is 1.14-class architecture — not a free upstream drop-in
  • Must preserve legacy wallet open path until migration completes
  • Keys and funds safety > elegance; dual-stack for a long time

Recommended implementation order

  1. Stabilize build and rebrand residuals (no storage change).
  2. Wallet SQLite dual-stack — biggest operator pain (BDB deps), clear migration story.
  3. Optional: RocksDB behind CDBWrapper for chainstate (lower risk than mdbx).
  4. Optional later: libmdbx if metrics justify the concurrency redesign.

Success criteria for any storage swap

  • Regtest full functional suite green
  • Mainnet reindex completes and tips match known good peer
  • Wallet migrate round-trips keys/balances on test wallets
  • Old and new clients interop on same network
  • Document operator steps (-reindex, migratewallet)
