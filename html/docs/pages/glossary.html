Glossary

Shared vocabulary so “conversion,” “consensus,” and “wallet DB” stay unambiguous.

TermMeaning here
Consensus Rules that determine which blocks/txs are valid. Changing these can fork the network.
Policy Node-local relay/mempool preferences. Can differ between nodes without forking.
Chainstate UTXO / tip index data used for validation; currently LevelDB-backed.
CDBWrapper Abstraction over the KV store for chainstate/index (obfuscation + cache hooks).
BDB / Berkeley DB Legacy wallet.dat engine. Painful dependency; migration target is SQLite.
Rebrand / conversion Bitcoin naming → Dogecoin naming in files, types, UI, docs — not a consensus change.
Header guard #ifndef BITCOIN_FOO_H style include guards (T3 rebrand work).
IBD Initial Block Download — syncing the chain from peers.
AuxPoW Auxiliary Proof of Work; enables merge mining.
DigiShield Dogecoin difficulty adjustment algorithm family used here.
GPE / GoPastEarth Optional multi-tenant business platform (POS, inventory, invoices). Not consensus. Settlement principle: native DOGE. See Payment layer.
Payment layer Merchant/app tooling for orders and invoices with final money on Dogecoin L1 — not an EVM rollup “L2.”
Native DOGE DOGE on the Dogecoin chain (not a wrapped or bridged IOU on another VM).
GigaWallet Foundation-oriented invoice/payment backend pattern for merchants (candidate adapter; not required for Core Pro local POS).
DogeConnect Payment-request style protocol for wallet/POS handshakes (design-level here).
Meme Stream Client-gated social/meme feed. SPA view-only; Core/Qt posts with publish key + wallet. Spec: MemeStream integration.
Allowlist Bitcoin strings we intentionally keep (copyrights, historical URLs).
Baseline tag Git tag once build + known features are frozen as recovery starting point.
Add terms whenever a discussion gets ambiguous.
