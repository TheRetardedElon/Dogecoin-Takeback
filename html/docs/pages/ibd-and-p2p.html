IBD & P2P robustness

Non-consensus work on Dogecoin Core Pro 1.14.101 so full nodes finish Initial Block Download faster and stall less — without touching AuxPoW, subsidy, or script rules.

Release line: 1.14.101 Docs: doc/ibd-p0-peer-telemetry.md Consensus: unchanged
Why this came first Gemini/Grok sequencing: measure and unstick IBD before assuming UTXO shortcuts. A broken peer graph or flush thrash makes AssumeUTXO irrelevant.

Problem

1.14 DNA uses a single tip and LevelDB chainstate. Long IBD is normal, but operators had little visibility when peers stalled, flushes hammered disk, or all connections clustered on the same network.

Delivery slices

SliceWhat shippedWhy
P0 telemetry IBDStats, RPC getibdinfo, debug category ibd, progress logging You cannot fix what you cannot measure during multi-hour syncs.
P0 stall rescue Non-preferred peers can fetch blocks when preferred downloaders stall (-ibdrescue, default on One slow “preferred” peer was a single point of failure for block fetch.
P0.1 flush policy Gentler IBD flush thresholds (less thrash under high -dbcache); prune UX tips in init Flush storms convert free RAM into disk waits during IBD.
P0.1 soft diversity Soft limit on many peers sharing the same IPv4 /8 Reduces correlated failure and eclipse-ish concentration without hard bans.
ASMAP Bitcoin-compatible -asmap; ASN-aware GetGroup when a map is loaded Peer diversity by real network topology, not only /16 prefixes.
P0.3 parallelism IBD: 32 blocks in transit per peer; up to 3 header-sync peers 1.14 defaults were conservative; more pipeline utilization on home links.
