Pure Dogecoin strategy

How we take Dogecoin back: native DOGE through Dogecoin Core — not an EVM “app layer,” not a second token, not a Trojan settlement brand.

Locked: 2026-07-28 Stack: dogecoind + dogecoin-qt + optional GPE POS RPC
North star One coin. One L1 ledger. Keys in Core. Merchants and tips settle as real DOGE. Client features (Meme Stream, Business/POS) are UX on top of that — never a detour into another crypto runtime.

What we build

  • Dogecoin Core Pro client — wallet, themes, Home, Business, Meme Stream
  • Native payments — Send/Receive, invoices, POS keypad → Core addresses
  • On-chain tips — author = wallet address; Tip opens Send (no bridge)
  • Optional merchant cloud (GPE) — business OS for multi-terminal shops; settlement still native DOGE (see Payment layer)
  • Storage dual-stack later — BDB → SQLite for wallets; consensus untouched

What we refuse

  • EVM / zkVM “app layers” as the product definition of Dogecoin
  • Wrapped DOGE / second ledgers sold as “the real Dogecoin experience”
  • Diverting Core users into non-Core stacks to use their own money
  • L2 / Drivechain / soft-fork programs until Core client + merchants are winning

Why this takes Dogecoin back

Competing on “Solidity deploys and TVL” forces foreign architecture. Competing on cash, POS, tips, and a trustworthy Core client makes native DOGE the obvious path — and starves diversion narratives of oxygen.
