GPENode — operator stack

What a GPENode is, what it is not, and how it plugs into Fast Sync and the multi-operator mesh. Public product docs only — no host secrets, passwords, or private keys.

Status: M1 live (first public operator) CDN: sync.doge.gopastearth.com Attested H: 6324519 Updated: 2026-08-10
One sentence GPENode is a headless Dogecoin operator host: run an honest full (or carefully pruned) node, dump UTXO snapshots, publish static files to a CDN, and optionally serve GPE merchant RPC over a private path. It is not consensus, not a second chain, and not Core Pro GUI.
Secrets stay offline IPs, SSH passwords, RPC credentials, and wallet material live only in operator-local files (e.g. gitignored serverdetails.txt / local/). Never paste them into this HTML site, public git, or chat logs.

One org (GPE today) can own both dump + CDN. Mesh maturity is when other orgs can dump and/or mirror the same digests. Full mesh design: Multi-operator mesh.

What GPENode is for

  • Fast Sync producer — dumptxoutset → file SHA-256 + hash_serialized → publish
  • Honest tip — mainnet (or regtest lab) node that stays synced
  • Optional GPE settlement RPC — private path for merchant watchers (addresses, received amounts) — not required for Fast Sync clients

What GPENode is not

  • Not Core Pro desktop (no Qt, Arcade, Meme Stream on the server)
  • Not a consensus authority or “trusted cloud chainstate”
  • Not a place to expose RPC on the public internet
  • Not live LevelDB on FUSE/Drive/object storage
  • Not mandatory for end users — clients only need HTTPS + hashes

  1. Keep dogecoind at tip on real block storage (NVMe / cloud block volume).
  2. Run snapshot script (e.g. make_utxo_snapshot.sh) → multi‑GB .dat + latest.json.
  3. Publish to CDN docroot over HTTPS (pull preferred: CDN host rsyncs from node).
  4. Clients: stream-hash file SHA-256 → load → mapAssumeutxo → activate → background prove.
  5. For a new height: map entry goes through the release process — CDN JSON alone is not the activation authority.

Binary requirement

Snapshot production needs a custom Core Pro / GPE daemon with AssumeUTXO RPCs (dumptxoutset, etc.). Stock upstream 1.14.9 alone is not enough for the dump path. Clients use the Windows (or other) Core Pro package with Fast Sync + WinHTTP.

Public CDN contract

Hostname: https://sync.doge.gopastearth.com/

  • latest.json — pointer (url, sha256, blocks, hash_serialized, bytes, …)
  • utxo-HEIGHT-TIMESTAMP.dat — multi‑GB artifact
  • Optional .sha256 sidecar and short status index.html

Mesh-ready manifests may add urls[] / mirrors[] while keeping the same sha256. Clients never accept a different digest from a “faster” host. See mesh page.

Operator kit (repo layout)

Private ops live in the GPENode worktree (C:\dogedevGPEnode when used), not mixed into end-user Core Pro docs:

PathKeep for
deploy/ Bootstrap, firewall, NVMe, snapshot, CDN handoff, conf examples
deploy/make_utxo_snapshot.sh Production dump → digests → latest.json
deploy/install_custom_dogecoind.sh Install daemon that has dump RPCs
scripts/ssh_cmd.py, node_status.py, run_remote_snapshot.py, … Remote ops helpers (GPE-only)
local/, serverdetails.txt Secrets — gitignored; never open-source

Win build scripts and Qt packaging that sync in from dogedev are Core Pro client noise on a pure operator tree — prefer scripts/sync-dogedev-to-gpenode.ps1 rules that preserve deploy/ and GPE-only paths, and do not treat the full client build farm as part of the public operator kit.

Open-source later (clean kit)

When publishing an operator kit without secrets, ship only:

  • deploy/*.sh examples with placeholders (no real IPs/passwords)
  • dogecoin.conf.example (localhost RPC, prune guidance)
  • CDN nginx sketch + sample latest.json
  • This HTML page + mesh + Fast Sync threat model
  • Checklist: dump → publish → verify curl/sha256

Do not ship: serverdetails.txt, wallets, live conf with rpcpassword, private keys.
