3. What we checked in this audit pass

  • ConnectBlock script-check lifetime vs CVE-2024-52911 pattern (still fixed)
  • RPC default bind behavior (httpserver.cpp)
  • UPnP default / miniupnpc presence (DEFAULT_UPNP=false)
  • dumpwallet path uses backup dir helper (not arbitrary system root by default)
  • Hardening flags in configure.ac (stack protector, FORTIFY, RELRO, PIE)
  • MemeStream image URL SSRF surface (allowlist + path + size + redirects)
  • No 0-day confirmed in this pass beyond known class issues already patched
  • No full fuzz campaign of P2P deserializers (out of scope for one pass)
  • No formal audit of all 1.14-era memory issues beyond known BTC disclosures
No undisclosed “0day” found this pass We re-checked UAF/UPnP status, RPC/P2P residual risk, and new Qt HTTP code. Residual risk is mostly operational (RPC exposure, same-process wallet+P2P, untrusted notify commands) and age-of-codebase (1.14-class needs ongoing backports). A determined audit firm could still find memory-safety bugs in P2P parsers — that is not evidence of current compromise.

5. Honest limits

Fixing CVE-2024-52911-class UAF removes one high-value remote crash/UAF path. It does not prove no other 1.14-era bugs exist. A full answer to “no other vectors” requires ongoing review, fuzzing, and tracking upstream Dogecoin/Bitcoin security disclosures — not a single commit.
