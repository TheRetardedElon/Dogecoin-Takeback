Modern UI & themes

Inventory of the custom Qt shell that survived. This is the main product differentiator over stock Dogecoin Core UI.

Live architecture (Phase 3 solidify — 2026-07-28)

LayerLive componentNotes
Shell DogecoinGUI inline sidebar + WalletFrame Not ModernMainWindow (still in tree, unused by main window)
Global theme ThemeManager (thememanager.*) Applied to qApp at startup; Options via ThemeSwitcher
Shell chrome DogecoinGUI::applyTheme / cycleTheme Styles #modernContainer / #modernNavigation
Full-window skins applyGlobalTheme Settings dialog theme picker (matrix, retro, …)
Single theme path EnhancedThemeManager (themes/theme_manager.*) is no longer linked into dogecoin-qt. Sources remain for a future experimental UI branch only. Dead *_fixed.h duplicates were deleted.

Experimental sources (not linked)

Kept on disk for a future UI rewrite; not in Makefile.qt.include:

  • modernmainwindow.*, modernnavigation.*, modernoverviewpage.*, moderncard.*
  • themes/theme_manager.* (EnhancedThemeManager)
  • customthemes.*, themebuilder.h, enhancedthemeswitcher.h

MOC-generated files may exist in tree — builds regenerate; avoid hand-editing moc_*.

Lost later ideas (rebuild candidates)

From prior design chat, not found as complete features in this tree:

  • Peer world map with ASN diversity, pin actions
  • Traffic graph broken down by P2P message class
  • Live bandwidth / connection sliders
  • ZMQ event sniffer tab, RPC playground, mempool heatmap
  • Meme Stream tab gated to client users

How to work on UI safely

  1. Prefer changing presentation only (stylesheets, modern* widgets).
  2. Keep WalletModel / ClientModel as data sources — do not put consensus logic in widgets.
  3. After theme changes, verify options dialog still inherits global theme.
  4. Screenshot baseline once build works; store under html/docs/assets/screenshots/ later.
